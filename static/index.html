二、手机摄像头接入方案选型分析

  • 方案 A（本项目采用 - 网页 WebRTC/WebSocket 采集）： 跨平台零安装！无论是 iOS 还是 Android，只需手机扫码即可直接通过浏览器调用手机摄像头，通过二进制流极速推向服务端换脸，体验丝滑，落地成本最低。
  • 方案 B（RTSP / DroidCam / IP Webcam）： 用户在手机安装 IP 摄像头 App，通过 RTSP 协议推流，抗弱网性能优秀，但需要用户额外安装 App。
  • 方案 C（纯端侧 Native 手机 App + CoreML / NCNN）： 算法全部运行在手机芯片上，无需服务器，但受限于手机算力与功耗发热，画质和分辨率需降级，开发与适配成本高。

三、现实场景瓶颈与法律合规红线

  • 遮挡与侧脸问题： 当人脸侧偏角度大于 60° 或手部、眼镜遮挡时，关键点对齐会出现跳动，需引入时序滤波或人脸分割掩码（Face Parsing Mask）防止穿帮。
  • 合规要求（重中之重）： 必须遵守《互联网信息服务深度合成管理规定》，换脸生成的视频画面必须打上“AI深度合成生成”的显著数字水印或文字标识，且采集源人脸需获得被替换人肖像权的合法授权。
